# Bug Audit — 2026-06-23

Ran 4 parallel bug hunts (payments, design/export, security, React runtime) + full
verification suite (server tsc / client tsc / vite build — all clean). Then **verified
every candidate against the real code** before fixing. Many high-severity reports were
false positives (agents read excerpts and missed adjacent guards).

## ✅ Fixed (verified real, safe, non-regressive)

1. **Credit deduction race** — `server/src/models/User.ts` `deductCreditsStrict`.
   Was read-modify-write; two concurrent deductions could both pass the balance check
   and lose a charge. Now compare-and-swap on `credits` (`.eq('credits', old)`) with a
   bounded retry. Atomic against contention.
2. **ConversationsList crash on corrupt cache** — `client/.../messaging/ConversationsList.tsx`.
   `JSON.parse(localStorage 'user')` had no try-catch; corrupt cache crashed the list. Guarded.
3. **Narration: stale `isPaused` closure** — `client/src/pages/ReaderPage.tsx`.
   `utterance.onend` captured a stale `isPaused`, so pausing mid-sentence didn't stop the
   chain. Added `isPausedRef` synced via effect.
4. **Narration not stopped on unmount** — `ReaderPage.tsx`. Added cleanup effect calling
   `speechSynthesis.cancel()` so speech doesn't keep playing after leaving the page.
5. **Password-reset token compare not constant-time** — `server/src/controllers/authController.ts`.
   `!==` on hashes → `crypto.timingSafeEqual` (defense-in-depth).
6. **Genome `lerpStep` div-by-zero guard** — `server/src/services/autoDesign/genome.ts`.
   `step<=0`/NaN would yield Infinity/NaN sizing. Added guard.

## ✅ Fixed — architectural batch 2 (2026-06-23)

7. **Author earnings double-pay** — `webhookController.ts handleBookPurchaseComplete`.
   The webhook re-credited the author even though the synchronous capture path already
   did (and set `revenueProcessed`). Added an idempotency guard at entry (skip if
   `revenueProcessed`) mirroring the top-up `creditsGrantedAt` pattern, and set
   `revenueProcessed: true` after processing so a webhook replay also no-ops.
8. **Email spam vectors** — `middleware/rateLimiter.ts`. Added per-RECIPIENT limiters
   keyed by target email (`skipSuccessfulRequests:false`): `passwordResetLimiter`
   (3/email/hr, wired on /forgot-password alongside authLimiter) and
   `inviteRecipientLimiter` (5/email/day, wired on the invite route).

- **PayPal order double-capture** (paymentController captureOrder TOCTOU at status check).
  Mitigated in practice by PayPal's own order state (2nd /capture errors) and by fix #7
  (no double-pay). A correct DB-atomic claim needs a new `'processing'` transaction status
  (schema/enum migration) — defer until that can be migrated + tested.
- **No atomicity in book-purchase revenue split** (5 sequential writes) — needs a DB
